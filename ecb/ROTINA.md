# Prompt da rotina na nuvem

Texto para colar em https://claude.ai/code/routines/trig_01We3sA7uPD2a3s8o5Cr4oQ5 (segunda 09:00).
A rotina precisa ter os dois repositórios: `vitorrgg/ecomplus-posts` e `vitorrgg/meu-livro`
(privado, com o texto do livro). Se mudar este arquivo, cole de novo na rotina: ela não lê daqui.

---

Você está no repositório vitorrgg/ecomplus-posts (branch master). Execute a rotina semanal: transformar os artigos mais lidos do E-Commerce Brasil em carrosséis de análise original da e-com.plus, escrever o post semanal da série do livro, deixar tudo na fila de publicação via PR e avisar a equipe no Slack. Leia ecb/README.md antes de começar.

Passos, nessa ordem:

1. `npm ci`.
2. `node scripts/ecb/mais-lidos.mjs --limite 3`. Isso grava ecb/semanas/<segunda>.json (a segunda-feira da semana corrente, fuso de São Paulo) com o ranking, as fotos livres para capa (`capasLivres`) e, em `escolhidos`, os até 3 artigos ainda não usados, já com o texto completo. Se o script falhar (o layout do site pode ter mudado, ou a rede do sandbox pode estar bloqueando o domínio), pule os passos dos artigos e relate o erro: nunca invente artigos. A série do livro (passo 4) continua mesmo assim.
3. Leia ecb/PROMPT.md (as regras editoriais; onde estiver {{RECURSOS}}, valem as linhas de ecb/recursos.md) e ecb/ESQUEMA.json (o formato de saída). Para cada artigo em `escolhidos` cuja url NÃO esteja em ecb/historico.json, escreva a análise seguindo exatamente PROMPT.md e o esquema, e salve como JSON em ecb/saidas/<segunda>/<posicao>.json, com um campo extra "fonte" igual à url do artigo. Inclua o campo `linkedin` (a versão escrita para o LinkedIn, regras no fim de PROMPT.md). Respeite os limites de caracteres descritos em cada campo do esquema: o layout é fixo. Não cite fonte, autor nem o portal; números só com o nome de quem fez o estudo. A capa de cada post usa uma foto diferente, escolhida entre as `capasLivres`.
4. Série do livro: `node scripts/ecb/livro.mjs`. Ele lê o livro no clone de vitorrgg/meu-livro ao lado deste repo (../meu-livro) e grava ecb/livro/rascunho/<segunda>.json com a pauta, o trecho do livro (`texto`), a ficha de dados verificados e as capas livres. Se ele disser que a semana já tem post do livro ou que a série está pausada, pule este passo. Se não achar o livro, relate e siga sem o post do livro. Com o rascunho, leia ecb/livro/PROMPT.md (as diferenças da série em relação ao ecb/PROMPT.md) e escreva ecb/saidas/<segunda>/livro.json no mesmo esquema, com "fonte" igual ao campo `url` do rascunho. A capa não pode repetir nenhuma das capas dos posts do passo 3. Nunca comite ecb/livro/rascunho/ (o .gitignore já exclui; não use git add -f): o texto do livro não pode ir para este repo, que é público.
5. `node scripts/ecb/gerar-briefs.mjs --from-json ecb/saidas/<segunda>`. Ele valida os JSONs (inclusive capa repetida e o chapéu "do livro · " da série do livro), grava posts/<slug>/brief.md, legenda.txt e linkedin.txt, põe a chamada do livro na legenda da série, atualiza ecb/historico.json e ecb/fila.json e imprime os slugs novos. Se reclamar de validação, corrija o JSON e rode de novo.
6. Para cada slug novo: `node scripts/render.mjs <slug>` e depois `node scripts/ecb/jpeg.mjs <slug>`.
7. Crie o branch `ecb/semana-<segunda>`, comite nele com a mensagem `feat(ecb): posts da semana <segunda>` incluindo ecb/, posts/ e output/ (os PNG e JPG fazem parte do commit), faça push do branch e abra um PR para a master com o mesmo título. Não tente push direto na master: o app do GitHub recusa. O workflow ecb-automerge.yml mescla o PR sozinho em seguida; não precisa esperar nem pedir review. Se o push do branch também falhar, relate o erro no resultado.
8. Avise no Slack, canal #conteudo (id C031BR9HY2K), uma mensagem por post novo, inclusive o do livro. Preferência: se as variáveis de ambiente SLACK_BOT_TOKEN e SLACK_CHANNEL_CONTEUDO existirem, rode `node scripts/ecb/notificar-slack.mjs <slugs>`: ele manda título, legenda e os slides como imagem e, logo abaixo, uma segunda mensagem com o texto do LinkedIn. Só se elas não existirem, use a ferramenta de envio de mensagem do conector Slack com: título da capa em negrito, subtítulo, número de slides, a legenda completa (posts/<slug>/legenda.txt), os links das imagens no formato https://raw.githubusercontent.com/vitorrgg/ecomplus-posts/master/output/<slug>/slide-N.jpg (um por linha), o texto do LinkedIn (posts/<slug>/linkedin.txt) num bloco de código para facilitar a cópia, e a frase "Entra na fila de publicação (análises seg/qua/sex 12:00, livro qui 12:00). Pra vetar, aprovado: false em ecb/fila.json." Não mande avisos extras sobre o PR ou sobre o estado do commit: o merge é automático. Se nenhum dos dois der, registre no relatório que o aviso não foi enviado.

No relatório final, liste os slugs gerados com o título da capa de cada um (indicando qual é o do livro e de qual pauta veio), o link do PR e se o aviso no Slack foi enviado (e por qual via). Não publique nada no Instagram: isso é o workflow ecb-publicar.yml, que roda sozinho segunda, quarta e sexta (análises) e quinta (livro) ao meio-dia.
